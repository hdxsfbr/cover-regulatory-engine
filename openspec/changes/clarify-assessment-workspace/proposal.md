# Proposal

## Why
The assessment exposes features in implementation order: project management and raw evidence precede the property and conclusions, and search results resemble selected properties. Users need a clear next action and comparable results without losing access to professional evidence.

## What Changes
- Separate search, explicit property selection, and the selected-property workspace; collapse introductory content once working.
- Put property identity and project type first, with map and assessment overview together.
- Present compact constraint rows with visible uncertainty and primary blockers; open supporting evidence on demand.
- Provide targeted next actions and reachable project inputs; retain all source inspection, conditional assumptions, map linkage and export.
- Move save/compare/follow-up/feedback into secondary project tools reachable from the workspace toolbar.
- Preserve asynchronous progress, cancellation, retry, historical scenarios, keyboard operation and mobile layout.

## Capabilities

### New Capabilities
None.

### Modified Capabilities
- `buildability-assessment`: Decision-ordered workspace with explicit selection, compact constraints and contextual next steps.
- `project-workspace`: Secondary but discoverable project tools that preserve state when opened and closed.

## Impact
Frontend main, workspace and stylesheet; existing browser tests and demo instructions. No API, rule, source, regulatory coverage or persistence changes. The same bounded single-family, detached ADU and guest-house packages remain; this does not add regulations or professional verification.
