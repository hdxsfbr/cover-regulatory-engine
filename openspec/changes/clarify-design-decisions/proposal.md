## Why
A browser walkthrough found six ambiguities that hide design conflicts or confuse current inputs with saved assessments. Professionals need proposal, limit, outcome and next action together.

## What Changes
- Show design comparisons in constraint rows and saved comparisons.
- Prioritize editing exceeded limits in next actions.
- Restore the latest saved design when opening a project and identify it.
- Only offer map links for existing annotations.
- Identify unsaved changes and prevent follow-up or feedback from silently targeting an older revision.

### New Capabilities
### Modified Capabilities
- `buildability-assessment`: Visible design outcomes, conflict actions and truthful map links.
- `project-workspace`: Explicit restored designs, useful comparisons and revision targeting.

## Impact
Frontend main/workspace components, shared comparison rendering, browser tests and demo documentation. Preserve backend rules, citations, immutable snapshots and API contracts. Regulatory coverage remains the existing SF/ADU/guest-house subset; no new legal conclusions or geometry derivation.
